### TC-F08-01

| Field | Value |
| --- | --- |
| Test case ID | TC-F08-01 |
| Title | Verify the dashboard shows Tickets issued, Gross Confirmed Revenue and Check-in Rate per BR-22 and updates them after new check-ins |
| Related requirement / use case | FR-F08-01, FR-F08-02 · UC-23 |
| Technique | Decision table, BVA |
| Priority | High |
| Pre-conditions | Shared seed loaded. `evt_published_paid`, `evt_published_free` and `evt_published_presale` belong to `org_club_a`, and every paid Reservation fixture below uses `tt_locked` (see section 6). In `evt_published_paid`: Tickets `tkt_issued_unchecked` (Not Checked In), `tkt_checked_in` (checked in only), `tkt_checked_out` (checked in and out); Confirming Receipts `rcpt_confirming_paid`, `rcpt_check_in`, `rcpt_check_out`, `rcpt_confirming` (`res_confirmed_unissued`, no Ticket), `rcpt_confirming_refunded` (`res_confirmed_refunded`, with `refund_full`); other receipts `rcpt_extra`, `rcpt_mismatch`, `rcpt_late`; Holding Reservations `res_holding_fresh`, `res_holding_expired`. `evt_published_free` has only `tkt_issued_free`. `evt_published_presale` has no Tickets. Signed in as `usr_organiser_club_a`. |
| Test data | Let R = the sum of `amount_vnd` of `rcpt_confirming_paid`, `rcpt_check_in`, `rcpt_check_out`, `rcpt_confirming` and `rcpt_confirming_refunded`, read from the database before the test. Check-in and check-out are done through the F07 scan API as `usr_checker_evt` (or the seed helper while F07 is not integrated). |
| Test steps | 1. Open the dashboard of `evt_published_paid`. 2. Compare the shown revenue with R and with a database sum over all Payment Receipts of the Event. 3. Open the dashboard of `evt_published_free`. 4. Open the dashboard of `evt_published_presale`. 5. Keep the `evt_published_paid` dashboard open and check out `tkt_checked_in`. 6. On the same open dashboard, check in `tkt_issued_unchecked`. |
| Expected result | 1. The page shows Tickets issued = 3, Gross Confirmed Revenue = R VND, Check-in Rate = 66.7% (2 of 3: `tkt_checked_in` and `tkt_checked_out`). 2. The shown revenue equals R. It does not include `rcpt_extra`, `rcpt_mismatch` or `rcpt_late`, and `refund_full` is not deducted (DT-F08-01 R1–R6). 3. Tickets issued = 1, Gross Confirmed Revenue = 0 VND, Check-in Rate = 0.0% (DT-F08-01 R7). 4. Tickets issued = 0, Gross Confirmed Revenue = 0 VND, Check-in Rate = 0.0% (default). 5. Within 5 s and without a page reload, Check-in Rate stays 66.7% and Tickets issued stays 3, because a Checked Out Ticket still counts as checked in. 6. Within 5 s and without a page reload, Check-in Rate changes to 100.0%. Tickets issued and revenue are unchanged. |
| Post-conditions | `tkt_checked_in` is Checked Out and `tkt_issued_unchecked` is Checked In. Reset the seed before re-running. |

### TC-F08-02

| Field | Value |
| --- | --- |
| Test case ID | TC-F08-02 |
| Title | Verify CSV export returns one row per issued Ticket of the Event in the exact format after writing an Audit Entry |
| Related requirement / use case | FR-F08-03 · UC-24 |
| Technique | EP, Decision table, Use case |
| Priority | High |
| Pre-conditions | Shared seed loaded. `evt_published_paid` belongs to `org_club_a` and has exactly three issued Tickets: `tkt_issued_unchecked`, `tkt_checked_in`, `tkt_checked_out`. `tkt_issued_free` belongs to `evt_published_free`. `res_confirmed_unissued` has no Ticket. Signed in as `usr_organiser_club_a` in session S1 and as `usr_approver_unit_a` in session S2. Count the Audit Entries with action CSV export before the test (seed includes `audit_csv_export`). |
| Test data | Before the test, set the `display_name` of the Attendee who owns `tkt_issued_unchecked` to `=HYPERLINK("http://x")` and of the owner of `tkt_checked_in` to `Nguyễn Văn "A", K48` (test-only DB update, see section 6). |
| Test steps | 1. In S1, open the dashboard of `evt_published_paid` and click Export CSV. Note the time the response starts. 2. Open the saved file in a hex viewer, then in a text editor. 3. Check the header and each row. 4. Check the time cells. 5. Check the text cells. 6. Search the file for the QR payload of each of the three Tickets (from the database), and for `password`, the stored password hash and any session or verification token. 7. Query the Audit Entries for the export. 8. In S2, call the CSV export API of `evt_published_paid` directly. |
| Expected result | 1. A file downloads with an HTTP 200 response. 2. The first three bytes are `EF BB BF` (UTF-8 BOM). Fields are separated by commas. 3. The header is exactly `ticket_id,event_title,ticket_type,attendee_name,attendee_email,payment_status,issued_at,check_in_at,check_out_at,attendance_state`. There are exactly 3 data rows, with `ticket_id` values of `tkt_issued_unchecked`, `tkt_checked_in` and `tkt_checked_out`. No row exists for `tkt_issued_free` or `res_confirmed_unissued`. Each row's `event_title` is the title of `evt_published_paid` and `ticket_type` is the name of `tt_locked`. 4. `issued_at`, `check_in_at` and `check_out_at` use ISO-8601 with `+07:00` (for example `2026-12-06T18:05:00+07:00`). `tkt_issued_unchecked` has empty `check_in_at` and `check_out_at`. `tkt_checked_in` has empty `check_out_at`. `tkt_checked_out` has both times. 5. The cell for `=HYPERLINK("http://x")` does not start with `=` in the raw file (neutralised, see section 6), and a spreadsheet shows it as text, not a link. `Nguyễn Văn "A", K48` is enclosed in double quotes with the inner quotes doubled and its diacritics display correctly. 6. No match is found. The file has exactly 10 columns. 7. Exactly one new Audit Entry exists: actor `usr_organiser_club_a`, action CSV export, target `evt_published_paid`, outcome success, with `occurred_at` not later than the time noted in step 1. 8. The API returns HTTP 403 with no file body. No new successful CSV-export Audit Entry exists for `usr_approver_unit_a`. |
| Post-conditions | One new Audit Entry for the export. Reset the seed before re-running. |

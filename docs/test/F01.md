| Field | Value |

| Technique | Decision table, State transition |

| Test steps | 1. In S1, open the edit page of `evt_draft`. In S2, open the scanner for `evt_published_paid`. 2. In S3, revoke the Organiser Role Assignment of `usr_organiser_club_a` for `org_club_a`. 3. In S1, without signing in again, reload the edit page of `evt_draft`, then call the `evt_draft` update API directly with the test data. 4. In S1, open the Catalogue. 5. In S3, lock `usr_checker_evt`. 6. In S2, without signing in again, reload the scanner and call any protected API. 7. In S2, sign in again with the `usr_checker_evt` credentials. 8. In S3, open the Audit Entry list and filter by the two target accounts. |

Sign-in is rejected with a text message that the account is locked, and no session cookie is set. 8. Exactly two new Audit Entries exist, written in the same transaction as each change: (i) actor `usr_admin`, action revoke Organiser, target `usr_organiser_club_a` / `org_club_a`, outcome success; (ii) actor `usr_admin`, action lock account, target `usr_checker_evt`, outcome success. Each has a timestamp. |
| Post-conditions | `usr_organiser_club_a` has no Organiser role for `org_club_a`. `usr_checker_evt` is locked. Reset the seed before re-running. |
